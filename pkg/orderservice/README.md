### Описание функций и структуры:

1. **OrderService**:
    - Предоставляет методы для работы с заказами, включая проверку их статуса в системе начисления баллов.
    - Содержит:
        - `ordersRepository`: Репозиторий для работы с заказами.
        - `baseURL`: Базовый URL системы начисления баллов.
        - `logger`: Логгер для записи событий.

2. **OrderResponse**:
    - Структура, представляющая ответ от системы начисления баллов.
    - Содержит:
        - `OrderID`: ID заказа.
        - `Status`: Статус заказа (например, "PROCESSED", "INVALID").
        - `Accrual`: Начисленные баллы.

3. **NewOrderService**:
    - Создает новый экземпляр `OrderService`.
    - Принимает:
        - `ordersRepository`: Репозиторий для работы с заказами.
        - `baseURL`: Базовый URL системы начисления баллов.
        - `logger`: Логгер для записи событий.
    - Возвращает указатель на `OrderService`.

4. **CheckOrdersForAccrual**:
    - Проверяет статус заказов, которые еще не обработаны (не имеют статуса `INVALID` или `PROCESSED`).
    - Возвращает ошибку, если не удалось получить список заказов.

5. **checkOrderStatus**:
    - Проверяет статус заказа в системе начисления баллов и обновляет его в репозитории.
    - Обрабатывает различные HTTP-статусы:
        - `429 Too Many Requests`: Повторяет запрос после указанного интервала.
        - `204 No Content`: Заказ не зарегистрирован в системе.
        - `500 Internal Server Error`: Внутренняя ошибка сервера.
        - Успешный ответ: Обновляет статус заказа в репозитории.

### Примечания:
- **Параллельная обработка**: Для каждого заказа статус проверяется в отдельной горутине.
- **Логирование**: Все ошибки и важные события логируются.
- **Обновление статуса**: Если заказ завершен (`PROCESSED` или `INVALID`), его статус обновляется в репозитории.
